## What

ACP v2 alpha.7 has no session update for the status of an MCP server. The FoundationModelsACPAgent session defines an extension update for it (agent tasks 3ywmbw4 and cbqsngc on the FoundationModelsACPAgent board). This task applies each update to `SessionModel.mcpServers` (task ^k8skz98). No FoundationModelsACP change is necessary: the update arrives as `SessionUpdate.unknown`.

### The message shape (agreed with the agent task; use it exactly)

Method `session/update`. `update.sessionUpdate = "_mcp_server_status"`. One update for each server.

- `name` (string, required): the key of the server.
- `transport` (required): `"stdio"` or `"http"`.
- `origin` (required): `"client"` or `"config"`. The client did not send the `"config"` servers, so the client adds an item for a name that it does not have.
- `status` (required): `"connecting"`, `"connected"`, `"failed"` or `"closed"`. For now the agent sends only `"connected"` and `"failed"`.
- `reason` (string, optional): only when `status` is `"failed"`. It is a fixed agent text with no URL, argument, env, header or error description.

Example:

```json
{"jsonrpc":"2.0","method":"session/update","params":{"sessionId":"01K9Z3M4Q8T2V6X0B5C7D9E1F3","update":{"sessionUpdate":"_mcp_server_status","name":"files","transport":"stdio","origin":"client","status":"failed","reason":"The command is not an absolute path."}}}
```

### Rules

1. The last update for a name replaces the status of that server.
2. Ignore a member that the client does not know. Ignore the whole update when `status`, `transport` or `origin` has a value that the client does not know, or when a required member is missing. Then nothing changes.
3. Do not give this update to `SessionMergeEngine`: the engine makes an `UnknownEntry` in the transcript from an unknown kind.
4. The agent sends the updates after the response of `session/new` and `session/resume`.
5. The agent sends them directly on the connection, not through its history sink, so they are not in a replay.

### Files

1. Add `Sources/FoundationModelsACPClient/Model/MCPServerStatusUpdate.swift`: an internal `struct MCPServerStatusUpdate` with `name`, `transport: MCPServerTransport`, `origin: MCPServerOrigin`, `status: MCPServerStatus`, and an internal `static func decode(_ update: SessionUpdate) -> MCPServerStatusUpdate?` that reads a `SessionUpdate.unknown` with kind `"_mcp_server_status"` from its raw JSON, and gives `nil` for each other update and for each update that rule 2 ignores. Map `"failed"` + `reason` to `.failed(reason:)`; ignore `reason` for each other status.
2. `Sources/FoundationModelsACPClient/Model/SessionModel.swift`:
   - In `fold(_:)` (line 276), before `promptCorrelator.observe` and `engine.apply`, give each update to `MCPServerStatusUpdate.decode`. A decoded update goes to a new internal `func applyMCPServerStatus(_ update: MCPServerStatusUpdate)`, and does not go to the engine.
   - `applyMCPServerStatus(_:)`: find the item by `name` and set its `status`. When no item has that name, append a new `MCPServerItem` with the `name`, `transport` and `origin` of the update, `server: nil`, and the status.
   - `updateTap()` keeps giving the raw update, as for each other update.
3. `Sources/FoundationModelsACPClient/Model/MCPServerItem.swift`: no new case is necessary; `MCPServerStatus` of task ^k8skz98 already holds each status. Add the wire values (`"connecting"`, `"connected"`, `"failed"`, `"closed"`, `"stdio"`, `"http"`, `"client"`, `"config"`) as `init?(wireValue:)` on the three enums.

## Acceptance Criteria

- [ ] An update changes the `status` of only the item with that name. The other items do not change.
- [ ] A later update for a name replaces the earlier status.
- [ ] `"failed"` with `reason` gives `.failed(reason: "…")`; `"failed"` with no `reason` gives `.failed(reason: nil)`.
- [ ] An update with `origin: "config"` for a name that the client does not have adds one `.config` item, with `server == nil`.
- [ ] An update with an unknown `status`, `transport` or `origin` value, or with a missing required member, changes nothing. An unknown extra member is ignored.
- [ ] The update adds no entry to `transcript`.
- [ ] `updateTap()` still gives the raw update.
