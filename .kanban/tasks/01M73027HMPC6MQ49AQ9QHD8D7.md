## What
ACPC-4, the first part. Add a general extension point to the client models. It has nothing that is specific to Testudo or SAH.

Today `ModelClient.extensionHandlers` (`Sources/FoundationModelsACPClient/Model/ModelClient.swift:112`) gives only `SAHGraphQLSubscriptions.extensionHandlers`. `ClientSideConnection` reads `Client.extensionHandlers` one time, at connect (FoundationModelsACP `Connection/ClientSideConnection.swift:123`). `connect(over:logger:bufferLimits:client:)` builds the router before it calls `wrap`. Thus an extension must be added before `connect`. `ExtensionHandlers` (FoundationModelsACP `Connection/ExtensionHandlers.swift`) has `public mutating func registerMethod<Params, Result>(_ method: String, params: Params.Type, handler: @escaping @Sendable (Params) async throws -> Result)` and `public mutating func registerNotification<Params>(_ method: String, params: Params.Type, handler: @escaping @Sendable (Params) async -> Void)`, and no merge. Thus each extension registers into one shared `inout ExtensionHandlers`. No change to FoundationModelsACP is necessary.

Decision (option D, see the comments): each extension registers into one shared `inout ClientModelExtensionHandlers`, an ACPClient struct that wraps one `ExtensionHandlers` and records each registered name.

The handlers run in the read loop of the connection and are not main-actor isolated (`SAHGraphQLSubscriptions` uses a `Mutex` for this reason). The observable state is on the main actor. Thus the design has two isolation parts.

Make these changes:
- [x] New file `Sources/FoundationModelsACPClient/Model/ClientModelExtension.swift`:
  - `public protocol ClientModelExtension: Sendable`. It is not main-actor isolated.
  - `associatedtype ConnectionState: AnyObject` (a `@MainActor @Observable` class, or a `Sendable` class with a `Mutex` when the handlers need it off the main actor). `@MainActor func makeConnectionState() -> ConnectionState`.
  - `nonisolated func registerHandlers(into handlers: inout ClientModelExtensionHandlers, context: ClientModelExtensionContext<Self>)`. The `Sendable` context gives `connectionLogger`, a `@MainActor` accessor of the connection state of this connection, and (for the next task) the `SessionModel` of a `SessionId`. A notification handler that changes main-actor state hops to the main actor. Document that a notification handler must return promptly, and that a request handler can wait.
  - `@MainActor func didInitialize(_ response: InitializeResponse, state: ConnectionState)`, default: do nothing.
  - `@MainActor func didClose(state: ConnectionState)`, default: do nothing.
  - State lookup uses the metatype of the extension as the key (`ObjectIdentifier(E.self)`), and one cast in one internal function. There is no lookup of an associated type through an existential in the public API.
- [x] `Model/ConnectionModel.swift`: `public func addExtension(_ extension: some ClientModelExtension)`. Do not use the name `register`: `ConnectionModel.register(_:)` for a `SessionModel` exists. While a connection is open, `addExtension` logs one diagnostic, and the extension takes effect at the next `connect`. Each `connect` makes a new connection state for each extension, before `wrap`. `public func extensionState<E: ClientModelExtension>(_ type: E.Type) -> E.ConnectionState?` gives the state of the current connection.
- [x] `Model/ModelClient.swift`: `extensionHandlers` builds one `ExtensionHandlers` from each extension, in the order of `addExtension`, plus the `SAHGraphQLSubscriptions` handlers (they move onto the point in a later task). When two extensions register the same method, the later one wins, and the model logs one diagnostic.
- [x] `Model/ConnectionModel+Initialize.swift` calls `didInitialize` of each extension after a successful `initialize`. The close path (`ConnectionModel.swift`, near `graphQLSubscriptions?.closeAll()`) calls `didClose`.
- [x] The doc comment of `connect(over:logger:bufferLimits:client:)` tells that a wrapping `Client` must forward `extensionHandlers` of the router, or each extension gets no message. DocC: one article that tells how a host writes and adds an extension.
