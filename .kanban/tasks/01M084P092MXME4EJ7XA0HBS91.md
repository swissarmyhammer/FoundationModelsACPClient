## What

`plan.md` -> **M7 -- Elicitation**.

Elicitation is a *request the user must answer*, the same shape as M3's permission requests. It becomes observable pending state the UI binds to and resolves.

**Unblocked 2026-08-19.** FoundationModelsACP rev e1f78ce ships the stable elicitation surface: the `Client` protocol has `createElicitation(_:)` and `elicitationComplete(_:)`, and `ClientCapabilities` has the `elicitation` field. The comments on this card hold the wire-surface notes.

Implemented shape:

- **Form mode** renders `requestedSchema` (flat primitives/enums) as bindable fields.
- **URL mode** must display the target host and obtain consent before navigation, must never carry credentials back over ACP, and closes on `elicitation/complete`. Those are spec obligations, not UI preferences.
- Reuse M3's pending-request machinery: continuation held, completed on answer, cancellation and agent-side withdrawal handled.
- **Home decision:** all pending elicitations live in one list on `SwiftUIACPClient` (`pendingElicitations`), because a request-scoped elicitation has no session. `pendingElicitations(for:)` filters for one session.

- [x] `elicitation/create` sets observable pending state for form and URL modes.
- [x] Form mode: answering resolves the agent's request with values that match `requestedSchema`.
- [x] URL mode: the target host is displayed, consent precedes navigation, and no credentials return over ACP.
- [x] `elicitation/complete` closes the pending URL-mode prompt.
- [x] Cancellation and withdrawal clear pending state and leak no continuation.
