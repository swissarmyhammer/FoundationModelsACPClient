## What

`plan.md` -> **M7 -- Elicitation**.

Elicitation is a *request the user must answer*, the same shape as M3's permission requests. It becomes observable pending state the UI binds to and resolves.

**Blocked upstream -- do not start yet.** Elicitation is **unstable-only** in v2: the vendored schema contains no elicitation methods, the stable `Client` protocol has only `sessionUpdate` and `requestPermission`, and the generated `MethodTable` lists `elicitation/*` only as unstable method info. Wait until `FoundationModelsACP` ships a stable elicitation surface (ACP's M8 tracks it), then re-verify the shape below against the vendored schema before implementation.

When the surface lands:

- **Form mode** renders `requestedSchema` (flat primitives/enums) as bindable fields.
- **URL mode** must display the target host and obtain consent before navigation, must never carry credentials back over ACP, and closes on `elicitation/complete`. Those are spec obligations, not UI preferences.
- Reuse M3's pending-request machinery: continuation held, completed on answer, cancellation and agent-side withdrawal handled.

## Acceptance Criteria

- [ ] `elicitation/create` sets observable pending state for form and URL modes.
- [ ] Form mode: answering resolves the agent's request with values that match `requestedSchema`.
- [ ] URL mode: the target host is displayed, consent precedes navigation, and no credentials return over ACP.
- [ ] `elicitation/complete` closes the pending URL-mode prompt.
- [ ] Cancellation and withdrawal clear pending state and leak no continuation.
