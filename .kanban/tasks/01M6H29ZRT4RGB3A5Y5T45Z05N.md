## What
Today each SessionModel reads its own update stream in its own task. The order between two streams is not fixed. Two bugs follow (found by AgentViewKit, resume with a nested replay):
1. A request for a grandchild (for example session/request_permission) can run before the child stream gave the grandchild announcement. The client has no model for the grandchild, so it answers cancel. The request is never pending.
2. The resume response ends the replay of every child model at once, before the child streams reached their end of history. A grandchild made late is treated as live, and a history snapshot confirms it.

Fix: ConnectionModel runs ONE consumer of the connection-wide ordered event stream of the wire (ACP board card 01M6H28VJY7H6QMQAYDX01SWP6, shortid x01swp6). The wire gives each event the session id, the event and a wire sequence number. The sequence shares one counter with Connection.currentRequestArrival, so an inbound request has a number that compares with the event numbers.

WAITS FOR the wire commit of that card (other board, so not in depends_on). Do not work around it before. The per-session subscriptions go, or stay only as a derived view: no backward compatibility, change each caller in the same change.

## Client work
- One consumer task in ConnectionModel applies each event, in sequence order, to the SessionModel of its session id. The model of a child that is not made yet is made when its announcement is applied, so the event that follows always finds the model.
- The resume marker is read one time at its wire position. The consumer ends the replay of the root model and of each child model that is replaying, at that position. A child model has no marker of its own.
- A request handler of the router (permission, elicitation) reads its arrival number first, then waits until the consumer applied a sequence at or above that number, and only then looks for the model of the session. The wait ends when the connection closes.
- A request for a session that is not in the tree after that wait is cancelled, as for any unknown session.
- The consumer ends when the stream ends or the connection closes. It ends the replay of each model as a failure and ends each update tap.
- Remove the per-session consumer task, and the code that gave the replay end to each model on its own (SessionModel+Stream.swift, ConnectionModel+Sessions.swift).
