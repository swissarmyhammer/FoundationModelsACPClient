## What

Request from AgentViewKit (card "Message timing"): the kit shows message timing and "Thought for N seconds". The kit binds directly to the observable models and keeps no state of its own, so the client models must hold the times.

This task covers the transcript entries only. It does NOT add a turn concept or turn times (the owner does not want a turn concept). "Ended" for a message or a thought uses an entry boundary or an idle agent state, not a turn object.

Spec facts (`../FoundationModelsACP/Schema/acp-v2.json`): no session update carries a time. The only date-time fields are `Annotations.lastModified`, `SessionInfo.updatedAt` and `SessionInfoUpdate.updatedAt`. The extensibility page says: "Implementations MUST NOT make assumptions about values at these keys" for `_meta`. Thus the client clock is the only source of each time. Do not read times from `_meta`.

Files (read first; adjust to the real structure):
- `Sources/FoundationModelsACPClient/Model/TranscriptEntry.swift` and each entry class (`UserMessageEntry`, `AgentMessageEntry`, `ThoughtEntry`, `ToolCallEntry`, `TerminalEntry`, `PlanTranscriptEntry`, `CompactionEntry`, `UnknownEntry`).
- `Sources/FoundationModelsACPClient/Model/SessionModel.swift` (the clock and the place where entries are made and changed).
- `Sources/FoundationModelsACPClient/Model/ConnectionModel.swift` (pass the wall clock to each `SessionModel`, as it passes `clock` today, line 140).

Approach:
- Add an injectable wall clock: `now: @Sendable () -> Date = Date.init` on `ConnectionModel.init` and `SessionModel.init`, beside the existing `clock: any Clock<Duration>`.
- On each entry class (a shared place, not a copy in each class): `public private(set) var startedAt: Date?`, `public private(set) var endedAt: Date?`, and `public var duration: TimeInterval?` (computed; `nil` unless both times exist).
- `startedAt`: the client time when the model first makes the entry from a live update, or when the prompt makes the local user message.
- `endedAt`:
  - Message and thought entries: the time when the next entry starts, or when an idle `state_update` arrives, whichever comes first.
  - Tool call: the time when its status first becomes `completed` or `failed` (and cancelled, if the schema has that status).
  - User message: equal to `startedAt`.
  - Other entries: the time when the next entry starts, or `nil` if the entry has no natural end. Write the rule for each kind in a doc comment.
- Replay (`isReplaying` is true) and history entries: both times stay `nil`. Never make a time for an entry that the client did not see live.
- Observation: each time is written once. Do not add a time that changes for each chunk, so that SwiftUI rows are not redrawn for each chunk. A chunk that the coalescer buffers must not change a time after it is set.
- Each time is set once. A later update does not move it.

## Acceptance Criteria
- [ ] With a fixed test clock, a live agent message gets `startedAt` at its first chunk, and `endedAt` when the next entry starts. `duration` is the difference.
- [ ] A thought gets `endedAt` when the next entry starts or when an idle `state_update` arrives, so "Thought for N seconds" can be computed.
- [ ] A tool call gets `endedAt` when its status becomes `completed` or `failed`, and later updates do not change it.
- [ ] The local user message of `SessionModel.prompt` gets `startedAt` when the prompt is sent.
- [ ] Each entry made during a replay has `startedAt == nil` and `endedAt == nil`.
- [ ] Many chunks of one message change `startedAt` and `endedAt` at most one time each (test with observation tracking).
- [ ] No turn type, turn property or turn time is added.
