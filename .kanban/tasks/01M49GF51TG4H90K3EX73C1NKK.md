title: 'Model: authState records each failed login and logout, with the operation and the reason'

## What

AgentViewKit binds to `ConnectionModel.authState`. Now `AuthState.failed(RequestError)` (`Sources/FoundationModelsACPClient/Model/AuthState.swift:22`) records only a `login(_:)` that the agent refuses with a `RequestError` (`Sources/FoundationModelsACPClient/Model/ConnectionModel+Initialize.swift:120`). These failures change no state:

- a `login(_:)` that fails with a `ConnectionError` (closed, timed out) or a `CancellationError`;
- each failed `logout(_:)` (`ConnectionModel+Initialize.swift:141`).

Also, a `.failed` value does not tell which operation failed, so the kit cannot show "sign-out failed" and "sign-in failed" differently.

1. Add `Sources/FoundationModelsACPClient/Model/AuthFailure.swift`:
   - `public struct AuthFailure: Hashable, Sendable` with `public let operation: Operation` and `public let reason: Reason`.
   - `public enum Operation: Hashable, Sendable { case login(AuthMethodId), logout, terminalLogin(AuthMethodId) }`. `terminalLogin` is for task "run a terminal auth method"; this task does not set it.
   - `public enum Reason: Hashable, Sendable { case request(RequestError), terminal(exitStatus: Int32?, message: String?) }`. Use `RequestError(reporting:)` (`Sources/FoundationModelsACPClient/Model/SessionModel+Prompt.swift:127`) to make a `.request` reason from any thrown error, so a closed connection, a time-out and a cancel each get one JSON-RPC form.
2. In `AuthState.swift`, change `case failed(RequestError)` to `case failed(AuthFailure)`. This is an API change; the kit is the only external user.
3. In `ConnectionModel+Initialize.swift`:
   - `login(_:)`: catch each error of the request (not only `RequestError`), set `authState = .failed(AuthFailure(operation: .login(request.methodId), reason: .request(RequestError(reporting: error))))`, and throw the error again.
   - `logout(_:)`: the same, with `.logout`. A logout that fails keeps no other state change.
   - `ConnectionError.closed` from `openConnection()` before the request goes out does not change `authState` (no request was made).
   - `ConnectionModelError.unsupported` from `requireCapability` does not change `authState`.

## Acceptance Criteria

- [ ] A login that the agent refuses gives `.failed` with operation `.login(methodId)` and reason `.request` with the error of the agent.
- [ ] A login that fails because the connection closed during the request gives `.failed` with reason `.request` and the `internalError` form of `ConnectionError.closed`.
- [ ] A logout that the agent refuses, or that fails on a closed connection, gives `.failed` with operation `.logout`.
- [ ] A call that sends no request (no open connection, or no capability) does not change `authState`.
- [ ] A later successful login still gives `.authenticated(methodId)`; a later successful logout still gives `.required(authMethods)`.
- [ ] Each existing test passes after the change from `.failed(RequestError)` to `.failed(AuthFailure)`.
