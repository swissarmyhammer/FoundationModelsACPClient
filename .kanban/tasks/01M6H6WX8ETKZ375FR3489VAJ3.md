## What
An independent review of the client at 2a5de93 gave 12 findings. The coordinator decided each one. One test for each fix, and each test fails on the old code (/tdd).

## FIX
- [ ] F2. A failed resume of an already open session wipes the transcript and closes the children before the outcome is known, and only mcpServers is restored. Add a rollback: keep the old state aside at the start of the replay, and restore it when the replay fails.
- [ ] F3. waitUntilApplied ignores task cancellation (and so $/cancel_request), and after the stream ended a late handler waits for ever. Make the wait cancellable, and return at once when the consumer has ended.
- [ ] F4. After a resume with no replayFrom, a child that the agent no longer announces stays for ever with an unknown state. When the resume sync is done and the linked tool call of a stale child is already final in the retained transcript, remove the child. Otherwise leave it unknown and document it.
- [ ] F5. restoreFailure is set only from a CURRENT snapshot, never from a history announcement.
- [ ] F6. Precedence of the parent mirror and the own state_update of the child: apply in wire sequence order, last writer wins. The skip compares with the LAST MIRRORED value, not with the current state of the child.
- [ ] F8. closedSessionIds leaks: prune it.
- [ ] F9. Events of unknown session ids fill the table: cap it per connection, with oldest-first eviction, and test it. Never drop the early events of a session that gets a model later if it is within the cap.
- [ ] F11. watchResumeStarts matches each session/resume start: match by the request id of this session.
- [ ] F12. childSession(for:) walks the whole tree: index it by session id.

## VERIFY BEFORE CHANGING
- [ ] F1. A pre-response subagent_update of a listed background item is history only in a resume WITH replayFrom. In a resume with no replay, it is current (RFD: "When no replay is requested, announcements, current snapshots, and ordinary child traffic may arrive before or after the resume response"). Check that the client does exactly that. Write the answer here. Change nothing if it does.

## DISMISSED (document only)
- F7. A child with no agentRun link stays until its parent closes. The rule stays. Document it in the README.
- F10. Requests for a child are answerable whatever its confirmation. The agent never sends a request during a replay. Keep the controls of an unconfirmed child disabled.
